# Writing, dirty and leaving the screen

Code can update a Form with the same safety as user input. Every write goes through the Normalizers, the Form Effects and the Validators, notifies listeners and never marks a Field as touched. There is no way to update a Field silently.

## patch

`patch` is generated with one named parameter per Field, typed as the Field.

```dart
form.patch(name: '  Marco ', note: 'vip');
```

- Only the Fields you pass are written. An omitted argument leaves the Field unchanged.
- It is one change: the Form Effects run once after the last write, and the Form and each changed Field notify once, so there are no intermediate rebuilds.
- **`null` means "leave unchanged", not "write null".** A null argument is the same as an omitted one, so `form.patch(phone: null)` does nothing. To choose null for a nullable Field, call `form.phone.setValue(null)` or use `replace`. To make a Field Unset, call `clear()`.

### Writing a chosen null in one change

`patch` cannot write null, but `batch` can. It runs any writes as one change, exactly like `patch`: one notification, and the Form Effects run once after the last write.

```dart
form.batch(() {
  form.notes.setValue(null); // a chosen null on a nullable Field
  form.name.setValue('Marco');
});
```

Use it when a change mixes nulls with other values and must not show an intermediate state. `batch` can wrap any writes, and writes to Nested Forms join the change of their parent.

## replace

`replace` sets every Field, Passthrough Fields included, from a Schema instance, as one change. Use it to load fresh data into an open form.

```dart
form.replace(const Contact(id: 2, name: 'Marco'));
```

`replace` leaves what the user did to the Form as it is: the Fields that were touched stay touched, and the new values are dirty against the old initial state. To load data as the new starting point, use [`reset(to:)`](#reset-and-commit).

## setValue and touched

`setValue` writes one Field. Pass `touched: true` to make the Field touched in the same change, so a widget without a moment of "losing focus" (a switch, a slider, a picker) can show its errors after the first interaction:

```dart
form.accepted.setValue(true, touched: true);
```

It is one notification, and it touches the Field even when the value did not change. A write without `touched` never touches the Field.

## touch and untouch

`touch()` marks a Field as touched. On a Form it touches every Field below it, Nested Forms, Field Arrays and Dynamic Forms included, with one notification, and skips an Unset optional Nested Form, as `submit()` does. Use it to show every error without submitting.

`untouch()` is the opposite, on a Field, a Field Array, a Dynamic Form and a Form: it clears touched and nothing else. Values, dirty and submitted stay as they are. On a Field Array, `touch()` touches only the array itself (a minimum number of items, say) and `untouch()` goes through every item.

```dart
form.touch();   // every error is visible
form.untouch(); // none of them is, the values are untouched
```

There is no public way to mark a Form as submitted: `submit()` is the only one.

## Dirty

A Field is dirty when its value or presence differs from its initial state, and so is the Form when any Field is. Changing a value and changing it back makes it clean again.

The initial state is what the Form holds once it has been created and its Form Effects ran, so a value derived by an Effect at creation is not dirty.

```dart
form.state.meta.dirty; // from SignUpFormState, a FormidableFormState
form.name.state.dirty; // FormidableFieldState
```

## reset and commit

- `reset()` returns every Field to its initial value and presence, clears its errors and forgets that it was touched or submitted. The Form Effects do not run: the initial state is already consistent, so reset restores it exactly.
- `reset(to: source)` replaces every value with a Schema instance and makes it the new initial state, so nothing is dirty, touched or submitted afterwards, and it is one change. It is not the same as `replace` followed by `commit()`: `replace` counts every Field it writes as changed, so its Effects run as for a user edit. An optional Nested Form is set or Unset as the source says. The Form Effects run on the new values as they do when the Form is created: no Field counts as changed, so an Effect that clears the province when the country changes does not clear the province you load. An Effect that derives a Field recomputes it.
- `commit()` makes the current state the new initial state. Call it after a successful save so the Form is no longer dirty, and a later `reset()` returns to the saved values.

All of them notify once, so a listener sees a single change.

```dart
// A fresh record arrived: show it as the new starting point.
form.reset(to: Contact(id: 2, name: 'Marco'));
```

`reset(to:)` also works on a Nested Form (`form.home.reset(to: address)`), which joins the change of its parent. It does not change whether a Form, a Nested Form or a Field Array is enabled. A Dynamic Form has no `reset(to:)` of its own, because it has no Effects: the `reset(to:)` of the Form that holds it resets its entries.

## FormidablePopScope

`FormidablePopScope` blocks leaving the screen while the Form is dirty. The system back gesture, the back button and `Navigator.maybePop` all call `confirmLeave`, where you show a confirmation and return whether to leave.

```dart
FormidablePopScope<ContactForm>(
  confirmLeave: (context) async =>
      await showDialog<bool>(
        context: context,
        builder: (context) => DiscardChangesDialog(),
      ) ??
      false,
  child: const ContactFields(),
)
```

While the Form is clean the screen is left without asking. The Form comes from the `form:` parameter or from the closest Form Scope. After saving, call `form.commit()` so the screen can be left.
