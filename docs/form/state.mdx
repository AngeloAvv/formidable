# State snapshots and reactive widgets

Every Field, Field Array and Form holds an immutable **state snapshot** and notifies its listeners synchronously when that snapshot changes. The snapshot of a Form is complete: it holds the state of everything below it, so a change anywhere, a typed character included, gives a state that is different from the previous one. Builders have the current snapshot from the first frame, so there is no empty first build. Formidable does not depend on bloc, but the widgets work the way you would expect from `flutter_bloc`.

## Field state

`form.username.state` is a `FormidableFieldState<T>`:

| Member | Meaning |
| --- | --- |
| `value` | The chosen value, or null while the Field is Unset |
| `isSet` | Whether the Field holds a value. Tells Unset apart from a chosen null |
| `status` | `valid` or `invalid` |
| `errors` | Every Validation Error of the Field |
| `touched` | The user interacted with the Field and left it |
| `dirty` | The value or presence differs from the initial state. Going back to the initial state makes the Field clean again |
| `enabled` | Whether the Field takes part in the Form |
| `submitted` | The Form was submitted since the Field was created |
| `pending` | An [Async Validator](/validation/async) is still checking the value |

## Form state

`form.state` is typed after the Form. The generator writes one state class per Schema, for example `SignUpFormState`, and `SignUpForm.state` returns it. It extends `FormidableFormState`.

The metadata of the Form is under `state.form`, a `FormidableFormMeta<SignUp>`. The Fields live next to it, so a Schema field can be called `status`, `dirty`, `pending` or `errors` without hiding anything. The generic `FormidableFormState`, used by the widgets that do not know the Schema, has the same `form`, so `state.form.status` reads the same either way.

| Member of `state.form` | Meaning |
| --- | --- |
| `status` | `invalid` while any Field has errors |
| `dirty` | Any Field is dirty |
| `pending` | Any Field is still waiting for the result of an [Async Validator](/validation/async) |
| `errors` | Errors of the Form as a whole, not tied to a Field |
| `isSet` | False only for an optional [Nested Form](/schema/nested-forms) that is Unset |
| `value` | The Schema instance while the Form is valid, not pending and set, null otherwise (typed as `SignUp?` in the generated state). It is lazy, see below |

And, on the generated state, one member per child, with the name of the Schema field (the name `form` is the only one a Schema field cannot use):

| Child | Type of its member |
| --- | --- |
| A Field | `FormidableFieldState<T>` |
| A Passthrough Field | its value, `T` |
| A Nested Form | the generated state of that Form, for example `AddressFormState` |
| A [Field Array](/schema/field-arrays) | `FormidableFieldArrayState<S>`, where `S` is the state of an item: `PhoneFormState` for Nested Forms, `FormidableFieldState<String>` for Fields |
| A [Dynamic Form](/schema/dynamic-forms) | `FormidableDynamicFormState`, which holds the state of what is registered, by key |

```dart
final state = form.state; // SignUpFormState
state.username.value;     // String?
state.address.street;     // FormidableFieldState<String>, in a Nested Form
state.phones.items.first; // PhoneFormState, in a Field Array
state.form.status;        // FormidableStatus
state.form.value;         // SignUp?
```

Equality is deep. Editing an item of a Field Array, adding, removing or moving one, or changing a Field of a Nested Form gives a state that is `!=` to the previous one. `state.form.value` does not take part in equality: it is derived from the states of the children, and a Schema is not required to define `==`.

### The value is lazy

The Schema constructor does not run when a state is published, so typing in a Field does not build a Schema nobody reads. `state.form.value` builds it from the states of the children on the first read, caches it, and gives the same instance on every later read of that state. Because it is built from the state and not from the live Form, a state you kept still gives the value it had, even after the Form moved on.

`form.value` is the `state.form.value` of the current state:

```dart
final signUp = form.value;
if (signUp != null) save(signUp);
```

## Notifications

A Field, a Field Array or a Form calls its listeners synchronously and only when its state is different from before. Because the state of a Form holds every child, `form.addListener` fires on every change below it: a value, `touched`, an error, an item added to an array. All of them have the shape of Flutter's `ValueListenable` (`state`, `addListener`, `removeListener`); `asValueListenable()` adapts them:

```dart
ValueListenableBuilder(
  valueListenable: form.username.asValueListenable(),
  builder: (context, state, _) => Text('${state.value}'),
)
```

## Builder, Listener and Selector

The three widgets exist for Fields, Field Arrays and Forms, and they mean the same everywhere:

- **Builder.** `builder(context, state)`. The first frame uses the current state. `buildWhen(previous, next)` receives two states and decides whether to rebuild. Without it every state change rebuilds.
- **Listener.** `listener(context, state)`, never for the state present when it is built. `listenWhen(previous, next)` decides whether to call it. Without it every state change calls it.
- **Selector.** `selector(state)` picks a value `R`. The widget rebuilds only when the picked value changes (`==`). The optional `buildWhen(previousR, nextR)` receives the previous and the next picked value and can still veto the rebuild.

## Field widgets

Field widgets always take the Field handle.

```dart
FormidableFieldBuilder<String>(
  field: form.username,
  buildWhen: (previous, current) => previous.status != current.status,
  builder: (context, state) => Text(state.status.name),
)

FormidableFieldListener<String>(
  field: form.username,
  listenWhen: (previous, current) => !previous.touched && current.touched,
  listener: (context, state) => log('left the username'),
  child: ...,
)

FormidableFieldSelector<String, bool>(
  field: form.username,
  selector: (state) => state.errors.isNotEmpty,
  builder: (context, hasErrors) => ...,
)
```

## Form widgets

The generator writes three typed widgets next to the Form Scope, in `*.formidable_scope.dart`. They need no type arguments, and the builder gets the generated state:

```dart
SignUpFormBuilder(
  builder: (context, SignUpFormState state) => Text(state.username.value ?? ''),
)

SignUpFormListener(
  listenWhen: (previous, next) => previous.form.status != next.form.status,
  listener: (context, state) => log('${state.form.status}'),
  child: ...,
)

SignUpFormSelector<bool>(
  selector: (state) => state.form.value != null,
  builder: (context, canSubmit) => FilledButton(
    onPressed: canSubmit ? () => save(context.signUpForm.value!) : null,
    child: const Text('Sign up'),
  ),
)
```

Each takes an optional `form`. Without one it looks up the closest `SignUpFormScope`, and throws an error that names the missing scope when there is none. `SignUpFormSelector` rebuilds only when the selected value changes, so a selector on `state.form.value != null` enables a button when the Form is valid and does not rebuild while the user types.

For code that does not use the generator, `FormidableFormBuilder<SignUpForm>`, `FormidableFormListener<SignUpForm>` and `FormidableFormSelector<SignUpForm, R>` do the same with the state typed as `FormidableFormState`, so you read `state.form.status` there too. `FormidableTypedFormBuilder<SignUpForm, SignUpFormState>` and its Listener and Selector are what the generated widgets extend; use them to get the typed state without the generated widgets.

## Field Array widgets

`FormidableFieldArrayBuilder`, `FormidableFieldArrayListener` and `FormidableFieldArraySelector` take the array. The state they get is the `FormidableFieldArrayState<S>` of the array, which holds the state of every item, so they follow an edit of an item too. The builder keeps handing out the keyed item widgets, see [Field Arrays](/schema/field-arrays#the-field-array-builder).

```dart
FormidableFieldArraySelector(
  array: form.phones,
  selector: (state) => state.length,
  builder: (context, count) => Text('$count phones'),
)
```

## Form Scope

`SignUpFormScope` creates the Form and disposes it. To expose a Form that you own, for example one created in your page state, use the `.value` constructor. The scope never disposes it:

```dart
SignUpFormScope.value(
  form: _form,
  child: ...,
)
```

Both take exactly one of `child` and `builder`. The builder receives the Form and a context below the scope, so the Form is usable right away:

```dart
SignUpFormScope(
  builder: (context, form) => Column(
    children: [
      FormidableMaterialTextField(field: form.username),
      // `context` is below the scope, so context.signUpForm works too.
    ],
  ),
)
```

Inside a scope, `context.signUpForm` returns the Form. If the scope has been given another Form, the Form widgets pick it up.
