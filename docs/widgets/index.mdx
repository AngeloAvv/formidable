# Field Widgets

A **Field Widget** shows one Field and writes what the user does back to it. Two layers provide them:

- **The base**, `FormidableFieldWidget<T, V>` in `formidable_flutter`, keeps the value, the focus and the errors of one Field in sync with one widget. It draws nothing, so it works with any widget, including third-party ones and widgets that have no text controller at all (a slider, a color picker, a rating). It owns its focus node unless you pass your own, and it never disposes the one you pass. `FormidableTextFieldWidget<T>` is its specialization for text.
- **Convenience widgets** for Material (`formidable_material`) and Cupertino (`formidable_cupertino`) are built on the base. The text fields take the whole API of `TextField` and `CupertinoTextField`.

Material widgets for every common input are described in [Material widgets](/widgets/material), and their Cupertino counterparts in [Cupertino widgets](/widgets/cupertino). To make any other widget a Formidable widget, see [Your own Field Widgets](/widgets/custom).

## The base

`T` is the type of the Field. `V` is the type of the value your widget works with, its **view value**. They are the same unless a [Codec](/widgets/codecs) sits between them.

```dart
FormidableFieldWidget<int?, int?>(
  field: form.rating,
  builder: (context, control) => StarRating(
    stars: control.value ?? 0,
    onChanged: (stars) => control.didChange(stars, touch: true),
    errorText: control.errorText,
  ),
)
```

The `builder` receives the **control**, the state object of the widget. It rebuilds whenever the Field changes. The control tells what to show:

| Member | What it is |
| --- | --- |
| `value` | The value to show: the Field seen through the Codec, or null while the Field is Unset. |
| `isSet` | Whether the Field holds a value. This tells Unset from a chosen null. |
| `state` | The `FormidableFieldState<T>` snapshot: errors, touched, dirty, submitted, pending. |
| `errorText` | The Validation Message to show, or null. It follows the [error display policy](/form/submit) and the [message lookup](/validation/messages). |
| `enabled` | Whether the Field accepts input. A disabled Field is not part of the Form. |
| `pending` | Whether an Async Validator is still checking the Field. |
| `focusNode` | The focus node of the widget. Give it to the widget that takes focus. |
| `textInputAction`, `onEditingComplete()` | The keyboard action and what it does, for [focus navigation](/widgets/focus). |

and takes what the user did:

| Method | What it does |
| --- | --- |
| `didChange(value, {touch})` | Writes the value through the Codec and the Field pipeline (Normalizers, Validators). With `touch: true` it also marks the Field touched. |
| `clear({touch})` | Puts the Field back to Unset. |
| `markAsTouched()` | Marks the Field touched, for an interaction that changed nothing, such as a cancelled dialog. |

A Field becomes touched when its focus node loses focus. A widget that cannot take focus has no "loses focus" moment, so its first interaction is what makes the Field touched: pass `touch: true`.

`didChange(null)` means "no value", with one exception: when the type of the Field admits null (`Color?`) and there is no Codec, null is a value the user can choose (a "none" option), and the Field is set to null. That is not the same as Unset (see [Unset is not null](/schema/presence)); use `clear()` to unset it.

Parameters shared by every Field Widget: `field`, `codec`, `messages` (see [Messages](/validation/messages)), `errorDisplay` (see [Submit, errors and disabled Fields](/form/submit)) and `focusNode`.

## Text

`FormidableTextFieldWidget<T>` is the same with `V = String`. Its control also owns the `TextEditingController`:

```dart
FormidableTextFieldWidget<String>(
  field: form.username,
  builder: (context, control) => TextField(
    controller: control.textController,
    focusNode: control.focusNode,
    onChanged: control.didChange,
    decoration: InputDecoration(errorText: control.errorText),
  ),
)
```

The control picks a [Codec](/widgets/codecs) between the Field and its text, so the same code works for an `int` or a `DateTime` Field. What the user types goes through `didChange`: it keeps the text on screen, even when a Normalizer such as `@Trim()` rewrote it in the Field, and text that cannot be parsed stays visible while the Field becomes invalid. You pass your own `textController:` if you need to hold it; it is then never disposed by the widget.
