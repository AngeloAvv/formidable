# Getting Started

This page builds a complete sign-up screen, step by step:

- an **email**,
- a **password** that must be strong,
- a **confirmation** that must match the password,
- a checkbox to **accept the terms and conditions**,
- a **Sign up** button that is enabled only while the form is valid and posts the result to an API.

You write one plain Dart class and the widgets. Formidable generates the rest.

This walkthrough uses Flutter, but the Schema, the generated Form and `submit()` are pure Dart: without Flutter you depend only on `formidable` and `formidable_generator` and use [the generated Form](/form) directly.

## 1. Install

Add the packages to `pubspec.yaml`. `http` is only there for the final request.

```yaml
dependencies:
  flutter:
    sdk: flutter
  formidable: ^0.2.0
  formidable_flutter: ^0.2.0
  formidable_material: ^0.2.0
  http: ^1.2.0
  material_ui: ^1.11.0

dev_dependencies:
  build_runner: ^2.4.0
  formidable_generator: ^0.2.0
```

`formidable` is the pure Dart core with the annotations. `formidable_flutter` binds a Form to the widget tree, and `formidable_material` gives you Material widgets that are already wired to a Form. Prefer Cupertino? Use `formidable_cupertino` instead, see [Cupertino widgets](/widgets/cupertino).

## 2. Declare the Schema

A **Schema** is a plain Dart class marked with `@Formidable()`. Every `final` field becomes a **Field** of the form, and a valid form hands you back an instance of this very class.

Create `lib/sign_up.dart`:

```dart
import 'package:formidable/formidable.dart';

part 'sign_up.formidable.dart';

@Formidable()
class SignUp {
  const SignUp({
    required this.email,
    required this.password,
    required this.confirmation,
    this.acceptedTerms = false,
  });

  @Trim()
  @Email()
  final String email;

  @MinLength(8)
  @HasUppercase()
  @HasDigit()
  final String password;

  @MustMatch(#password)
  final String confirmation;

  @IsTrue()
  final bool acceptedTerms;
}
```

`part 'sign_up.formidable.dart'` is where the generator writes its code. Then, field by field:

- `@Trim()` is a **Normalizer**: it removes the whitespace around the email before the Field is validated.
- `@Email()`, `@MinLength(8)`, `@HasUppercase()` and `@HasDigit()` are **Validators**. Each one is an annotation, and each one reports its own typed error, so a weak password can tell the user exactly what is missing. They run only while the Field has a value. The [Validator catalog](/validation) lists the rest.
- `@MustMatch(#password)` is a **cross-field rule**. It lives on the Field that shows the error and names the other Field by symbol, so a typo in `#password` is a build error, not a runtime surprise.
- `@IsTrue()` requires the checkbox to be `true`.

Required-ness comes from the type. `email`, `password` and `confirmation` are non-nullable `String`s with no default, so they are **Required Fields**: until the user types something they are **Unset**, which is different from empty and from null, and the form cannot be submitted. `acceptedTerms` has a default of `false`, so it always has a value and `@IsTrue()` judges it. Without the default, an untouched checkbox would be an Unset Required Field and would report "required" instead of "must be accepted". See [Required and optional Fields](/schema/presence).

## 3. Generate the code

```sh
dart run build_runner build
```

For `sign_up.dart` the generator writes two files next to it:

- `sign_up.formidable.dart` declares `SignUpForm`, the live form. It is a pure Dart class with a typed getter per Field (`form.email`, `form.password`, `form.confirmation`, `form.acceptedTerms`), and it is what produces a `SignUp` when the form is valid.
- `sign_up.formidable_scope.dart` declares `SignUpFormScope`, which creates a `SignUpForm` and makes it available to the widgets below it, and `SignUpFormSelector`, `SignUpFormBuilder` and `SignUpFormListener`, which rebuild or react when its state changes. It is written only when your package depends on `formidable_flutter`.

In an app, generated files are usually not committed. Add them to `.gitignore` and run `build_runner` in CI:

```gitignore
*.formidable.dart
*.formidable_scope.dart
```

If you publish a package to pub.dev instead of building an app, keep the generated files in the archive: pub leaves out what `.gitignore` matches, so commit them or add a `.pubignore` that does not list them, and run `build_runner` before `dart pub publish`.

While you work, `dart run build_runner watch` regenerates them on every save.

## 4. Show localized messages

A Validator never produces text: it produces a typed error, and the widget turns it into the **Validation Message** the user reads. Install the localizations delegate once, next to the delegates of your app, to get the built-in messages in English, Italian, Spanish, French and German. Create `lib/main.dart`:

```dart
import 'package:formidable_flutter/formidable_flutter.dart';
import 'package:material_ui/material_ui.dart';

import 'sign_up_page.dart';

void main() => runApp(
  MaterialApp(
    localizationsDelegates: [
      FormidableLocalizations.delegate,
      ...GlobalMaterialLocalizations.delegates,
    ],
    supportedLocales: FormidableLocalizations.supportedLocales,
    home: const SignUpPage(),
  ),
);
```

Without the delegate nothing breaks, but errors fall back to their plain English string form. See [Messages and localization](/validation/messages) to change the wording or add messages for your own errors.

## 5. Build the page

Create `lib/sign_up_page.dart` with the scope and the four fields. The submit button comes in the next step.

```dart
import 'package:formidable/formidable.dart';
import 'package:formidable_material/formidable_material.dart';
import 'package:material_ui/material_ui.dart';

import 'sign_up.dart';
import 'sign_up.formidable_scope.dart';

class SignUpPage extends StatefulWidget {
  const SignUpPage({super.key});

  @override
  State<SignUpPage> createState() => _SignUpPageState();
}

class _SignUpPageState extends State<SignUpPage> {
  @override
  Widget build(BuildContext context) => SignUpFormScope(
    create: SignUpForm.new,
    builder: (context, form) => Scaffold(
      appBar: AppBar(title: const Text('Sign up')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          FormidableMaterialTextField(
            field: form.email,
            keyboardType: TextInputType.emailAddress,
            decoration: const InputDecoration(labelText: 'Email'),
          ),
          FormidableMaterialTextField(
            field: form.password,
            obscureText: true,
            decoration: const InputDecoration(labelText: 'Password'),
          ),
          FormidableMaterialTextField(
            field: form.confirmation,
            obscureText: true,
            decoration: const InputDecoration(labelText: 'Confirm password'),
          ),
          FormidableMaterialCheckboxListTile(
            field: form.acceptedTerms,
            title: const Text('I accept the terms and conditions'),
          ),
          // The Sign up button goes here.
        ],
      ),
    ),
  );
}
```

`SignUpFormScope` creates the Form with `create`, disposes it with the page, and gives it to `builder` together with a context below the scope. `SignUpForm.new` builds an empty form: every Required Field starts Unset.

Each widget takes a Field and nothing else. `field: form.email` is a `FormidableField<String>`, so a text field bound to `form.acceptedTerms` (a `bool`) does not compile.

`FormidableMaterialTextField` is a Material `TextField` kept in sync with its Field:

- it shows the Field's value and updates the Field as the user types;
- when the user leaves it, the Field becomes **touched**, and from then on its Validation Message appears under the text field. Nothing is red while the user is still typing the first time;
- when a Field has several errors, the first one in the order of the annotations is shown;
- it takes every parameter of `TextField` (`obscureText`, `keyboardType`, `decoration`, ...). Your `decoration` is merged with the message instead of being replaced by it.

The checkbox works the same way: the first tap touches the Field, so an unticked box shows its message only once the user has interacted with it. Every widget decides when to show an error with the same policy, which you can change, see [Submit, errors and disabled Fields](/form/submit#when-errors-are-shown).

## 6. Enable the button while the form is valid

The button should follow the state of the Form. Instead of checking validity inside `onPressed`, read the validity from the Form state and let Flutter rebuild the button when it changes. `SignUpFormSelector` does exactly that:

```dart
SignUpFormSelector<bool>(
  selector: (state) => state.meta.valid,
  builder: (context, valid) => FilledButton(
    onPressed: valid ? () => _onSubmit(form) : null,
    child: const Text('Sign up'),
  ),
),
```

Put it where the comment is in step 5.

- `selector` picks one value from the typed `SignUpFormState`. `state.meta.valid` is true when no Field has an error. It also stays true while an asynchronous check is still running, because nothing has failed yet, so read `state.meta.pending` as well if the button must wait for it.
- The Selector rebuilds its `builder` only when the picked value changes. Typing a character that keeps the form invalid does not rebuild the button, and the one keystroke that makes the form valid enables it.
- A button with `onPressed: null` is disabled, so the callback never has to ask whether the form is valid.

The state has more to select from, such as `state.meta.status`, `state.meta.dirty` and `state.meta.pending`. See [State and reactive widgets](/form/state).

## 7. Submit

`_onSubmit` goes in `_SignUpPageState`. `submit()` waits for any pending asynchronous check and returns a sealed result: `FormidableSubmitValid` carries a `SignUp`, and `FormidableSubmitInvalid` carries the errors. An exhaustive `switch` handles both.

```dart
Future<void> _onSubmit(SignUpForm form) async {
  switch (await form.submit()) {
    case FormidableSubmitValid(:final value):
      final response = await http.post(
        Uri.parse('https://api.example.com/sign-up'),
        headers: {'Content-Type': 'application/json'},
        body: jsonEncode({'email': value.email, 'password': value.password}),
      );
      if (!mounted) return;
      final message = response.statusCode == 201
          ? 'Welcome aboard!'
          : 'Sign up failed (${response.statusCode}).';
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(message)),
      );
    case FormidableSubmitInvalid():
      break; // The errors are already shown on the Fields.
  }
}
```

Add the two imports it needs at the top of the file:

```dart
import 'dart:convert';

import 'package:http/http.dart' as http;
```

`value` is a `SignUp`, so `value.email` is a `String`, already trimmed and validated. Nothing is cast and nothing is read from a map.

The button only runs while the form is valid, so the `FormidableSubmitInvalid` case is rare in this flow. It can still happen, for example when an asynchronous Validator rejects the value while `submit()` waits. In that case `submit()` has already marked every Field as touched, so every error is visible, and it has moved the focus to the first invalid Field. See [Submit, errors and disabled Fields](/form/submit) to apply errors returned by your server back onto the Fields.

Run the app: the button is disabled, and it turns on once the email is valid, the password has eight characters, an uppercase letter and a digit, the confirmation matches and the terms are accepted.
